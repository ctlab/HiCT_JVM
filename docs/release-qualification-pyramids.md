## Thirty-minute workload

The installer ran one browser context across a mixed-resolution FASTA map, mat18, the combined 4DN map and the Aedes draft. Each return to the FASTA map verified a painted blue landmark at 1 bp. The workload included navigation, repeated map changes, editing and figure export. It recorded frame time, input acknowledgement and process memory, with five minutes of warm-up for memory trends.

The first run overlapped with native desktop qualification. It completed 218 cycles in 1,802.7 s. Frame p95 was 16.7 ms and input acknowledgement p95 was 67.7 ms. The server RSS slope was +1.574 MiB/min, above the +1 MiB/min limit. Used JVM heap grew at +0.055 MiB/min. Per-map RSS varied substantially, with the largest samples after the Aedes map. The recorded measurements do not establish a cause. [First run](../build/release-evidence/pyramids-linux-2bbe44cb/first-run/soak/results.json)

The isolated repeat passed after **1802.3 s across 225 cycles**, including 57 returns to the fine-overlay fixture. The initial mixed-fixture pyramid took 0.79 s to generate. Subsequent attachments had a p95 of 46.7 ms. All four individual map performance gates also passed.

## Reproducing the checks

The packaged runner accepts an extracted Linux package, the paired WebUI commit, a prepared Borrelia directory and the three additional maps. It starts the package's own API and WebUI, verifies served assets, and exercises the menu, rendering, cache, boundary, structural, offline, performance and soak stages. Each package also ran the large-display whole-genome and automatic legacy Jobs cases on an independent server. The same test is now a standard runner stage.
