# Sequence analyses and assembly edits

Implementation on `feature/sequence-analysis-20261013`, extended by
`fix/sequence-lifecycle-20261014`, based on JVM `412768ac` and WebUI `9706538`.
The running publication campaign is a different, frozen
build; its results must not be relabelled as measurements of these features.

## Sequence coordinates

The current default preserves explicit imported AGP gaps and uses a configurable
1,000-N separator between scaffolds in concatenated analysis sequences. The Open
Wizard and sequence dialogs expose the server setting. Zero is an explicit opt-in
to gap-free joins. New singleton/scaffold gaps use the configured default;
changing it does not rewrite imported gaps. The environment/system property
`HICT_EXPORT_GAP_LENGTH_BP` sets the startup default. UI changes apply to the
running server; restarting uses its configured environment default.

Normal FASTA export emits one record per scaffold and preserves its internal
AGP gaps. Selection export may concatenate pieces with separators. Contact-matrix
coordinates remain gapless: no synthetic contact bins or ATUs are introduced,
and biological inter-scaffold Hi-C contacts are not discarded. Search subjects
and ModDotPlot's expanded contexts stop at positive-length gaps. Alignment
chaining can still span long ambiguous regions; padding alone is not a guarantee
against all gapped alignments.

[AGP 2.1](https://www.ncbi.nlm.nih.gov/genbank/genome_agp_specification/) distinguishes
`N` (explicit size) from `U` (unknown size represented by 100 bases). A chosen
1,000-N separator is an analysis/export policy, not an inferred biological gap
length, and is not a `U`-gap. Separate FASTA scaffold records need no inter-record
padding.

Every job captures an immutable path of original FASTA source intervals before
it starts. All coordinates inside the implementation are zero-based half-open.
Background jobs must never re-read a mutable assembly halfway through a run.
Results carry the captured path fingerprint, source identity, parameters, tool
version, and completion status. Source intervals, not transient assembly offsets,
anchor overlays and search hits. The same assembly edits project both maps.

A cached similarity value is evidence about the sequence used to calculate it.
Moving that evidence with a fragment does not recompute similarity across a new
join. Provenance must preserve that distinction. Search-hit projection checks
whether the complete matched path still exists and remains contiguous, forwards
or reverse-complemented. Deleted, split, or rearranged pieces retain the query
identity and are explicitly labelled; viewport clipping alone is not a split.

## ModDotPlot: algorithm, licence, and storage

Upstream [ModDotPlot](https://github.com/marbl/ModDotPlot), pinned to
`1616ae94f5b7e22190a8eb50b6df2e3798a18d0b` (version 1.0.0), estimates sequence
identity from modimizer sketch containment in overlapping sequence windows.
Its native kernel includes ntHash code with a separate MIT notice. Both MIT
notices must accompany distribution; Python dependencies need their own notices.
The bundled palettes also require the upstream ColorBrewer Apache-2.0 notice and
additional attribution conditions; these are retained in `third_party/moddotplot/`.

Citation: Sweeten AP, Schatz MC, Phillippy AM. ModDotPlot—rapid and interactive
visualization of tandem repeats. *Bioinformatics* 40(8), 2024, btae493.
[doi:10.1093/bioinformatics/btae493](https://doi.org/10.1093/bioinformatics/btae493).

| Storage | Assessment |
| --- | --- |
| Scalar fixed-point identity in the existing numeric matrix | Preferred. Colours remain a rendering palette; numerical values remain meaningful. Record the scale and analysis type in optional metadata. |
| RGB packed into int64 | Rejected: summing, balancing, and querying packed colours produces meaningless values. |
| Additional channels | Useful for genuinely independent measurements, unnecessary for a scalar identity palette. Would require a format and reader extension. |

Identity levels must be computed at each window size, not generated by summing
finer cells. Coverage metadata must distinguish uncomputed areas from computed
zeros/below-threshold identity. Compatible region updates replace only their
coverage, atomically; changed scientific parameters select a different overlay.
Atomic publication must leave the last valid sidecar intact on cancellation.

## Sequence search choices

[SeqKit](https://github.com/shenwei356/seqkit), pinned to version 2.13.0,
tag commit `d13b5fa388cc869de05abe1bdb07980eef5efb4e`, is MIT licensed and provides
cross-platform exact and substitution-mismatch searches via `locate`.
[Official search documentation](https://bioinf.shenwei.me/seqkit/usage/#locate).
Mismatch mode does **not** support indels and must not be presented as BLAST.
The release payload builds this exact SeqKit source with Go 1.25.5,
CGO disabled and baseline GOAMD64=v1. Linked Go dependency notices and the Go
runtime licence are included. Initial developer tests used an upstream release
binary; those tests are not the identity of the final source-built payload.
Both-strand searching, exact/mismatch mode, and current-assembly/selection scope
must be explicit controls before submission. FASTA headers and generated IDs for
plain one-sequence-per-line input must survive into track tooltips.

Citation: Shen W, Sipos B, Zhao L. SeqKit2: A Swiss Army Knife for Sequence and
Alignment Processing. *iMeta*, 2024, e191.
[doi:10.1002/imt2.191](https://doi.org/10.1002/imt2.191).

[NCBI BLAST+](https://blast.ncbi.nlm.nih.gov/doc/blast-help/developerinfo.html)
provides local similarity alignment, including gaps, but heuristic searches are
not exhaustive substring searches. NCBI government code is public domain, with
third-party exceptions in the [toolkit licence](https://github.com/ncbi/ncbi-cxx-toolkit-public/blob/main/LICENSE).
The Linux x86_64 payload adds BLAST+ **2.16.0**, compiled from its SHA-256-pinned
source archive in manylinux2014. This version builds with that platform's GCC 10;
2.17.0 requires C++20 constructs not supported by the compiler. NCBI's official
2.17 Linux binary requires glibc 2.28 and is deliberately not shipped as a
manylinux2014 binary. Public-domain and third-party notices are collected under
`share/licenses/sequence-analysis/blast/`; see `third_party/blast/`.

BLAST runs locally with usage reporting disabled. The UI exposes strand, identity,
query coverage, E-value and maximum subject-record controls. It uses `blastn-short`
if any query is shorter than 50 bases, otherwise `blastn`; low-complexity masking
is disabled. A subject is a complete gap-free sequence segment, not a small
arbitrary chunk: this avoids losing alignments at artificial chunk boundaries.
Segments above BLAST's signed 32-bit length limit are rejected explicitly. The
record cap defaults to 500 and can omit weaker hits. BED features span each HSP's
subject coordinates, including indels, and tooltips retain query coordinates,
identity, E-value, bitscore and gap counts. Raw `blast-hits.tsv` is retained.

Windows x64 and both native macOS architectures bundle the official NCBI
2.16.0 distribution, pinned by SHA-256. Windows also includes nghttp2 and
app-local release Visual C++ runtime DLLs, with their notices and hash receipts;
no separate runtime installation is needed on Windows 10/11. `HICT_BLASTN_BIN`
remains an optional override. Every platform must pass a real gapped alignment
before packaging and again from the JAR-extracted executable. BLAST is an
additional method, not a replacement for exhaustive exact search.
HOMER is outside this feature's scope.

Citation: Camacho C et al. BLAST+: architecture and applications. BMC
Bioinformatics 2009;10:421. https://doi.org/10.1186/1471-2105-10-421.

Native packaging must pin payload hashes, retain notices, and execute a small
known-answer search/identity fixture in CI on each target. AVX variants are only
appropriate where the selected upstream kernel supports and benefits from them;
CPU-compatible baselines must remain available. CI configuration is not evidence
that Windows/macOS execution has occurred until those jobs actually run.

## Implemented behaviour and portable builds

The File menu provides separate ModDotPlot and active-assembly alignment dotplot
dialogs. Both accept the whole active assembly or a selected row/column rectangle,
with explicit parameters and streamed job logs. The primary map can remain in
the upper triangle while the generated sidecar appears in the lower triangle.
Search offers SeqKit exact/substitution matching and local BLAST gapped alignments.
It does not claim HOMER motif discovery.

ModDotPlot stores identity percentage multiplied by 10,000 in legacy int64
contact records. Each resolution is computed independently. Alignment dotplots
store sampled alignment counts, following the existing PAF sampling convention;
these are not identity scores or CIGAR-exact nucleotide alignments. Both formats
retain original source-bin/ATU identities and add optional analysis metadata.
No existing input contact map is overwritten. Compatible updates produce new
immutable sidecar versions, replacing only newly computed coverage (including
zeros), retaining prior scores elsewhere. Incompatible parameters choose a new
overlay. Coverage metadata distinguishes computed zeros from uncomputed areas.

The sparse writer avoids allocating a dense physical block (an 8192-square
int64 block would require 512 MiB). Per-block geometric capacity avoids quadratic
append storage during tiled updates. Computational sketches are batched; large
contact matrices are not materialized as a single dense array.

Selection context actions include reversal, movement, debris, sequence search,
both dotplot methods, FASTA export and PNG/SVG/PDF export. Structural edits act
on the diagonal intersection and retain the server's whole-scaffold invariant.
Selection exports retain vector labels/tracks and crop the captured scene;
heatmap cells remain raster pixels. The view is restored afterwards.

The sequence payload is built from pinned sources, with dependency notices,
archive hashes, native startup tests and known-answer fixtures. The Linux build
uses manylinux2014 with a SHA-pinned python-build-standalone CPython 3.12.12
runtime. All 197 ELF payload files passed the GLIBC <=2.17 check and native
execution in that container. The minimap2 and AVX2/AVX512 mm2-plus binaries in the benchmark kit were
also rebuilt and executed in manylinux2014 after the laptop gate exposed an
older Ubuntu-24.04 mm2-plus requiring glibc 2.38. All three rebuilt aligners
require at most glibc 2.14 and start on Ubuntu 22.04. The benchmark kit does not
add the unrelated older hictk binary; the normal release workflow builds hictk
separately and performs its existing ABI validation. The kernels do
not offer justified AVX2/AVX512 variants; baseline portable builds are used.
Existing accelerated alignment choices remain available.

The reusable GitHub Actions workflow builds and executes known-answer fixtures
on Linux, Windows, macOS ARM64 and macOS x86_64. Portable releases depend on
these jobs and merge their verified payloads before packaging. At this initial milestone, Windows/macOS
execution was pending; the later platform validation is recorded below.
Local configuration alone is not proof of a successful remote build.

## Limits to disclose

* Cached identity follows source bins through assembly edits. It is not silently
  recomputed at a changed join; job metadata retains its original sequence path.
* Attaching a secondary map currently begins a new edit journal, as the existing
  application does. The dialog warns explicitly and permits saving without
  attaching. Once attached, the two maps follow the same assembly edits.
* Region updates copy the prior sidecar before atomic publication; cost grows
  with that file. Managed superseded matrices are removed only after a finished,
  reopenable replacement exists and the old matrix is detached. Cleanup follows
  replacement chains; logs, prepared FASTA inputs and receipts remain. Cancellation keeps the previous
  valid matrix. User inputs and unrelated files are never cleanup targets.
* Jobs run through one bounded worker/queue. The current server retains the most
  recent 32 completed jobs in memory; durable job files survive but restart-time
  discovery in the UI is not implemented.
* Widely separated selected axes currently export their bounding sequence span.
  This is correct but may do unnecessary FASTA I/O between those axes.
* Search does not automatically rerun after edits. A track-level warning and
  feature tooltip say “New matches might have formed”. Original hits follow source
  intervals; a new gap through a hit marks it fragmented. Undoing to the original
  sequence/gap state clears the warning. Fingerprints and projections are cached
  once per track query, not rebuilt for every hit.
* External binary overrides are supported but are not authenticated as the
  bundled upstream build. Executable hashes and job settings preserve provenance.

## Lifecycle revision (14 October 2026)

History checkpoints contain persistent roots owned by each open ChunkedFile.
Attaching another file cannot reconstruct its earlier roots by simply replaying
inverse operations: native splits can remove bins, debris excludes intervals,
and AGP imports replace the layout. Creating/reprojecting a checkpoint for every
historical state is a separate feature. Attachment/replacement/detachment therefore
starts a new journal and is explicitly disclosed in the UI. Existing edits are
not undone when the journal is reset.

Generated overlays store cells against **original physical bins**. Opening one
validates original contig names, FASTA intervals, resolutions and ATUs before
replacing the existing source. The candidate is then given the primary's current
AGP layout and visibility. This supports reopening the original map after making
an overlay in an edited order; an incompatible source is refused even if a
legacy mismatch override is requested. Axis identity is checked, not a full
checksum of FASTA contents. Legacy non-generated secondary maps retain their
existing compatibility workflow.

Remapping a stored dotplot is not recomputation. Values whose windows included an
old join still describe that calculation; especially ModDotPlot's expanded context
can affect more than one edge bin. Provenance and the dialog disclose the need
to regenerate for changed joins. No fixed time-to-recompute is promised.

“Bounding FASTA interval” means that rows at 1–2 Mb and columns at 100–101 Mb may
require a temporary sequence spanning 1–101 Mb. Only the selected matrix rectangle
is scored/stored, so this is an I/O and temporary-space cost, not additional
reported comparisons. Sequence search's **bounding interval** scope, in contrast,
intentionally searches the intervening sequence too; its UI states the coordinates.

The minimap now fits its actual content box and allows the zoom-out needed by
viewports smaller than OpenLayers' default 256 pixels. The blue viewport is the true intersection of the projected visible
extent with minimap bounds. It is not translated/resized to fit. The container
clips drawing, and the existing drag-to-navigate interaction is preserved.

Validation for this revision is recorded separately from the 13 October evidence
and frozen remote performance campaigns. Do not label those historical timings
as measurements of this revised version.

The final 14 October checks reported 247 JVM tests (243 passed, four optional
integration tests skipped), 12 Python tests passed with one optional skip,
and passing WebUI type checks, DTO/resolution/viewport regressions and production
build. Eleven Chromium 140 application scenarios passed with no unexpected

BLAST alignment, exact matching across an explicitly gap-free join, post-edit
warnings, minimap edge/full-view clipping, accumulated overlay cleanup, selection

PDF rasterization differed from PNG by 0.944/255 mean channel error; 1.373% of
pixels differed by more than 10/255. Vector labels remain editable. Rendering
across output formats is not claimed to be bit-identical.

The source-built BLAST 2.16.0 executable and copied SQLite/OpenMP runtimes passed
a real insertion-containing alignment inside the pinned manylinux2014 image.
Their maximum GLIBC requirements are 2.14, 2.14 and 2.17 respectively. The rebuilt
ModDotPlot adapter passed its native fixture and all 196 ELF files were within
GLIBC 2.17. These checks used explicit native-tool overrides with the test JAR;

release execution still required actual GitHub Actions results; see the later

## Displaying generated overlays (2026-10-14)

Generated sidecars intentionally store only selected resolutions. Attachment first
verifies original contig/FASTA intervals and physical ATUs, projects the current
assembly, and compares dimensions by matching base-pair resolution. A missing
unused resolution is not a reason to require manual confirmation. Source mismatch
or an incomplete sidecar remains an error, including with `allowMismatch=true`.

The generation dialog reports saved output separately from display attachment.
It offers an inline compatibility confirmation for generic mismatches, and a
saved-result retry without repeating computation. Dotplots are secondary matrix
layers; annotation/sequence-search tracks are 1D layers. Manual attachment remains
available under View → Tracks and layers.

`MODDOTPLOT_IDENTITY` is a color expression over unchanged numeric identity scores.
It uses reversed ColorBrewer RdYlBu-11 (blue → yellow → red), the stored identity
threshold/scale, and transparent missing or below-threshold values. No Cooler
weights or resolution scaling apply to identity scores. Sidebar and graph-editor
presets support identity below the diagonal and multicolor compositing. The graph
editor preserves this expression when loading, editing, and exporting a pipeline.
The map format and computation algorithm are unchanged.

Regression coverage includes a real two-resolution map with a one-resolution
sidecar, split/reversed assembly attachment, accumulation, independent aligner
selection output, inline confirmation, pipeline round-trip, selection PNG/SVG/PDF
export, and reattachment in original assembly order. Palette tests check eleven
colors, missing values, and a 100% threshold.
